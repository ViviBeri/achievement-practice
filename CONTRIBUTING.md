# Contributing

Thank you for helping improve this repository.

## Before you start

- Check existing issues and pull requests to avoid duplicating work.
- Keep changes focused on one topic.
- Use clear, descriptive names for branches and commits.

## Branch workflow

1. Create a branch from `main`.
2. Make the proposed change.
3. Review the diff and check the rendered Markdown.
4. Commit with a message that describes the change.
5. Open a pull request against `main`.

## Pull request checklist

- [ ] The change has a clear purpose.
- [ ] Documentation matches the repository's current behavior.
- [ ] Markdown headings, links, and code fences render correctly.
- [ ] The pull request explains what changed and why.

## Reviews and merging

Respond to review feedback and update the branch when needed. Merge only after the change has been checked and any required reviews or status checks have passed.

For documentation-only changes, verify the rendered preview and test any links or commands that the change introduces.
